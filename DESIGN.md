# John Scott Dynasty — Design System

**Version:** Phase 2 foundation · November 13, 2026  
**Source of truth:** `app/globals.css`, the `--ds-*` CSS custom properties, and their Tailwind v4 `@theme inline` aliases.  
**Review surface:** `/ui-design-system` is available on **Vercel Preview** and an explicitly enabled local fixture, not Production.

This is a *sports-native mobile interface*, not a generic SaaS dashboard. The design should support scanning a fantasy lineup and comparing actual/projected results quickly. Dark surfaces, cyan highlights, real hockey imagery, and efficient controls remain the identity.

## Non-negotiable continuity

1. **Preserve real NHL player portraits.** Do not remove, replace with initials/icons, mask out, or swap to AI-generated faces. The authoritative portrait source is `getPlayerPhoto()` in `lib/hockey-data.ts`; reuse `PlayerPortrait` for new rows, and preserve existing source URLs and broken-image fallback. A 32–40px photo is the standard list size; 64–80px is appropriate for a player detail. Position indicators are complementary, **never substitutes** for the real image.
2. Preserve team logos, injury/status labels, meaningful position colors, the four main destinations, and horizontal swipe affordances.
3. Do not edit Prisma schema, scoring, lineup locking, draft/waiver/trade rules, or persistent league data for a visual task.
4. Preserve the 430px shell constraint and functionality at 320px. Phase 3 owns navigation and shell relocation; Phase 4–6 own the substantial per-screen redesigns.
5. A preview with no database must remain explicitly **SAMPLE DATA · READ ONLY**. Never present fixtures as real league scores.

## Colors and semantic usage

Use classes generated by `@theme inline` such as `bg-background`, `bg-surface`, `bg-surface-raised`, `text-foreground`, `text-text-secondary`, `text-text-muted`, `border-border`, `text-brand`, `text-success`, `text-warning`, `text-danger`. In shared UI controls, `primary`, `secondary`, `popover`, `muted`, `ring` and `destructive` are aliases to the same palette.

| Semantic token | Value | Use |
| --- | --- | --- |
| `--ds-canvas` | `#070a12` | App background |
| `--ds-surface` | `#0d1424` | Roster/list/score cards |
| `--ds-surface-raised` | `#122035` | Dialogs, sheets, elevated cards |
| `--ds-surface-hover` | `#17283f` | Hover/selected background |
| `--ds-border` | `#2b415d` | Structural dividers |
| `--ds-border-strong` | `#395878` | Input or emphasized borders |
| `--ds-text` | `#f1f6ff` | Names, score totals, titles |
| `--ds-text-secondary` | `#b3c3d8` | Secondary body text |
| `--ds-text-muted` | `#95abc4` | Readable, lower priority metadata |
| `--ds-accent` | `#19d9e3` | Active destination, actionable focus, CTA |
| `--ds-focus` | `#6be6f4` | Visible keyboard focus |
| `--ds-success` | `#69e0b0` | Confirmed success (not projected wins) |
| `--ds-warning` | `#f7ce79` | Injuries, pending concerns |
| `--ds-danger` | `#ff91a4` | Errors and dangerous actions |

The muted text color has **8.39:1** contrast on canvas, and **7.79:1** on the standard surface. The accent has **11.38:1** on canvas. This is deliberate: the legacy `#5e7090` and `#45546d` were too low-contrast for small text. All values are intended for dark surfaces; color combinations on success/warning surfaces should still be checked at point of use.

**Position colors** are separate tokens for C, W, F, D and G. Center/wing/flex use white text on darker badges; D/G use dark ink on the lighter badge. The `PositionBadge` component uses the mappings. Keep textual position letters, so color is never the sole signal.

Do not add arbitrary hex values directly to JSX when a semantic token exists. If a new semantic meaning truly requires a color, add the token centrally and update this document.

## Spacing and density

The canonical scale is **4, 8, 12, 16, 24, 32px**, named `--ds-space-1/2/3/4/6/8`. Use Tailwind `gap-2` (8px), `gap-3` (12px), `gap-4` (16px), `gap-6` (24px) and equivalent padding utilities. Keep arbitrary distances out of one-off components.

- Screen gutters: 16px (`px-4`) unless a dense two-column matchup requires less.
- Cards: 16px padding by default, 20px for complex content.
- Section separation: 24px.
- Major content-group separation: 32px.
- Control and sheet corner radii: 12–20px.
- Touch targets: **44×44px** for primary actions, navigation, roster mutations, claim actions, trade submissions, and modal dismiss buttons. Compact score-table controls may be visually smaller only if their actual interactive target remains large enough or they have adequate spacing.
- Portrait sizing: 32–40px for dense lists; 64–80px for detail. **Never shrink a portrait to solve a spacing problem**; adjust adjacent text or metadata first.

Data density is a feature in fantasy sports. Improve legibility without artificially making every row tall.

## Typography hierarchy

Use the system font stack until a real typography review proves another face is preferable; do not add remote fonts by default.

| Role | Size | Weight | Notes |
| --- | --- | --- | --- |
| Screen title | 24px | 700–800 | One dominant heading |
| Section heading | 18px | 650–750 | Distinguish functional groups |
| Player name / body | 14–16px | 400–700 | High contrast |
| Secondary game/team info | 12–13px | 400–600 | Must remain legible |
| Dense table label | 12px | 600–700 | Label metrics explicitly |
| Score | 18–28px depending on context | 700–800 | Use tabular numerals |

Avoid making every label bold and uppercase; reserve all caps for small section labels and positions. Numbers should use `tabular-nums` or `ui-stat-number` so refreshing points do not shift columns.

**Actual vs projected points:** Always label both. Never compute or display a win probability from a ratio of projected team points. True win percentages require an explicitly validated model, otherwise omit them.

## Component library

Source | Responsibility
--- | ---
`components/ui/button.tsx` | Accessible Base UI buttons. Variants: default, outline, secondary, ghost, destructive, link. Default 44px; smaller sizes are explicit exceptions.
`components/ui/tabs.tsx` | Base UI tabs with visual selected state, keyboard navigation and clear focus.
`components/ui/badge.tsx` | Secondary status and short labels.
`components/ui/sheet.tsx` | Shared mobile drawer, semantic elevated surface, accessible close target.
`components/ui/dialog.tsx` | Shared modal surfaces and focus handling.
`components/ui/hockey.tsx` | `HockeySurface`, `HockeySectionHeading`, `HockeyStatus`, `PositionBadge`, `HockeyStat`.
`components/hockey/player-portrait.tsx` | Real NHL photo, original source/cropping, initials fallback only on actual image failure.

When adding a new component, prefer these primitives. Keep business rules inside existing domain services. For a transactional action, a standard button is preferable to a nested `div[role=button]`.

## Interaction, focus and motion

- Every interactive element must be keyboard reachable with visible focus. Semantic HTML controls are preferred to clickable spans. Focus ring token: `--ds-focus`.
- Use Base UI's native tab, sheet and dialog keyboard behavior rather than building parallel focus systems.
- Respect `prefers-reduced-motion`; transitions and CSS animation are effectively disabled in that mode. Spring-driven swipe components should continue to apply their existing motion preference logic.
- Motions should communicate selection, navigation or state; don't add scroll entrance animations, constant pulses, glowing gradients or distracting hover shifts.
- Distinguish idle, loading, disabled, error, successful and empty states through labels as well as color.
- Do not let floating chat or sticky controls hide action buttons.

## Reference gallery and testing

The real React components, not a static mock, are displayed at `/ui-design-system` under a safe **Vercel Preview** or local `UI_VISUAL_FIXTURES=1` session. The route is explicitly disabled on Vercel Production. The gallery contains static fixture names and real NHL headshot sources, and performs no database writes.

Run:

```bash
npm run test:visual
npm run test:preview
npm run test:production-no-db
npx tsc --noEmit
npm run build
```

The Phase 2 preview test also checks token colors, nonoverflow at phone widths, keyboard navigation, touch targets, and headshot presence. Production-data E2E tests remain gated by the Phase 0 isolated local database requirement.
